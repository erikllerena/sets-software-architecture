# REFERENCES — Software Architecture & Design

Estas fuentes apoyan el estudio; no constituyen un curso obligatorio ni reemplazan la explicación del tutor. Consultar la edición y vigencia antes de recomendar una lectura específica.

- **C4 Model:** https://c4model.com/ — comunicar sistemas mediante vistas de contexto, contenedores, componentes y código cuando corresponda.
- **arc42:** https://arc42.org/overview/ — estructura práctica para documentar arquitectura y decisiones.
- **SEI ATAM:** https://www.sei.cmu.edu/library/architecture-tradeoff-analysis-method-collection/ — análisis de trade-offs entre atributos de calidad; los ejercicios de SETS son inspirados en estas ideas, no un ATAM formal.
- **AWS Well-Architected Framework:** https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html — ejemplo de un marco de calidad ligado a un proveedor; contrastar sus recomendaciones con el contexto y alternativas.
- Bass, Clements y Kazman, *Software Architecture in Practice* — atributos de calidad, decisiones y evaluación.
- Richards y Ford, *Fundamentals of Software Architecture* — estilos, patrones y trade-offs.
- Martin Kleppmann, *Designing Data-Intensive Applications* — modelos de datos, consistencia, distribución y fiabilidad.

## Uso crítico de las fuentes

- Primero identifica la pregunta conceptual; después busca una fuente que aporte una respuesta o matiz.
- Diferencia principios generales de recomendaciones condicionadas por proveedor, versión o entorno.
- No presentar una fuente como evidencia de que una solución es siempre correcta.
- Si una afirmación depende de una versión actual o de una garantía técnica concreta, verifica la documentación oficial pertinente.
- No replicar guías exhaustivas de frameworks aquí. Todo concepto necesario para este programa debe poder explicarse en este Proyecto aunque el ejemplo utilice una tecnología específica.
